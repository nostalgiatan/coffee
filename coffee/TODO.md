# 清单

V1 的目标:只要 x86-64,系统 `cc` 做链接器,不用 LLVM,不用 Rust 也能构建和测试。

## 已完成

- [x] 机器码后端是默认,LLVM 已移除
- [x] 种子构建:只用 `cc` 就能得到 `coffee2` 和 `tea`
- [x] `tea test`:每个测试独立目录,并行,600 秒超时
- [x] 兼容测试:1023 个用例全部通过(Rust 集成测试中适用于编译器的部分都已移植)
- [x] stage0(Rust 编译器)自举得到不动点
- [x] 嵌套 fn、匿名 fn、模块级 `let`
- [x] 同名的嵌套 `class` 出现在两个函数里:驱动在前端之前把重名的改成 `名字__n<函数号>`(`driver/src/nested.cf`)
- [x] 复合赋值 `+=` `-=` `*=` `/=` `//=` `%=`(解析成 `t = t op v`)
- [x] f-string 的 `{}` 里可以是任意表达式,类型 `str`、整数、浮点、`bool`
- [x] `use f as g in m`:展开时在本文件里把 `g` 换成 `f`(`driver/src/alias.cf`)
- [x] f-string 的整数和浮点转文字用 Coffee 自己的实现(`rt/src/fmt.cf`,最短往返),不再依赖 `snprintf`
- [x] 元组、切片、`buf<T>` 的全局变量
- [x] 模块别名 `use m as a`:本文件里的 `a.f(x)` 去掉前缀(`driver/src/alias.cf`)
- [x] f-string 的格式说明(`{x:5}`、`{n:08x}`、`{x:.2}`)、`{{` `}}` 转义、`{}` 里的字符串字面量
- [x] 浮点字面量:任意指数、最多 18 位有效数字,按最近偶数舍入(`5e-324`、`1.7976931348623157e308`);`float(4)` 仍只认短的
- [x] `buf_ptr(b)` 只借用缓冲区,取出的是数据指针
- [x] 增量编译:`--incremental dir`,每个源文件一个 `.o`,按记号和别的文件的接口算键(`driver/src/incr.cf`);`tea build` 默认用
- [x] `tea build`、`tea run`;包含目录写进 `coffee.toml` 的 `[build]`/`[test]`,不再用 `tea.toml`
- [x] 或模式里绑定变量(各分支同名同类型,穷尽性检查算上每个分支)
- [x] `obj.assign("字段", v)` 对需要释放的字段(`str`、类):先算出新值,再释放旧值
- [x] 全局变量:`str`、类、枚举、定长数组(就地读写,不能搬出;整体赋值先释放旧值)
- [x] 尾表达式返回、`for` 的各种形式、`&` 取址、或模式、类模式、f-string

## 编译器性能

- [ ] 二元运算直接用寄存器操作数(现在都先装进 rax/rcx)
- [x] 自举编译从约 68 秒降到不到 2 秒:`s[i]` 每次都要 `strlen` 做边界检查,词法和解析改读字节数组
- [ ] `str` 没有长度,下标和 `len` 都是 O(n);考虑给 `str` 加长度(会动 C 互操作和所有分配点)
- [x] 增量构建的键:每个文件每个记号都查一次所在文件(平方级),2 秒降到 0.1 秒;命中路径现在约 0.7 秒(展开 0.35、改名 0.1、解析 0.1、哈希 0.1)
- [x] 增量构建并行:`-j n` 起 n 个进程各编一部分文件;冷构建 42 个文件的 降低+代码生成 从 0.9 秒到 0.35 秒;`--time` 看各阶段
- [x] 并行的负载:按记号数从大到小分给当前活最少的进程;自举编译器 `-j 8` 的编译阶段从 378 毫秒到 209 毫秒
- [x] 每个函数一个 `.text.<名字>` section;`cfld` 的 `gc` 和 `cc -Wl,--gc-sections` 都能丢掉没人调用的函数
- [x] 跨文件内联:小函数和小方法(≤60 记号,无嵌套 fn)的函数体算接口的一部分,看得见它们的文件把它们也降低一遍只为内联;循环里调另一个文件的小函数,增量构建 1.54 秒,和整程序构建一样 0.57 秒
- [ ] 字符串常量和全局变量按个丢弃:量过,编译器的 `.rodata` 25 KB、`.data` 56 字节,共占 1%,不值得;代码 2.2 MB 才是体积的大头
- [x] `buf<类>` 的元素赋值:新缓冲区的元素是零,赋值时先判空再释放旧值(原来对空指针释放而崩溃)
- [x] 增量构建的前端只检查过期文件的函数体(别的文件的函数体当作声明);改一个文件的函数体,前端从 0.55 秒到 0.07 秒;f-string 运行时由各文件的 `.rt` 标记决定要不要链接,不再为判断它多跑一遍前端
- [x] 增量构建的依赖细到符号:一个文件的键只含它的记号提到的项(及其接口再提到的项)的接口;新加一个没人用的函数只重编它自己的文件(原来全部重编)
- [x] 没改动的重建从约 0.55 秒到 0.25 秒:展开时别名改写原来把每个文件转成 `str`(逐字符拼接,`strlen` 占了一半时间),改成直接词法分析字节;改类名和解析合用一棵树
- [ ] 展开、解析、哈希仍然每次整个程序做一遍(共约 0.2 秒);要再快就得按文件缓存展开后的文本和声明摘要(`.cfi`)

## 第一代(Rust)有而现在没有的

第一代已归档(标签 `rust-stage0-final`,说明在 `docs/explanation/stage0.md`)。要不要补回来,各自决定:

- [ ] 从 `.h` / `.c` 生成 `.cfc`(`-c`),`[dependencies.c_libraries]` 的依赖图
- [ ] 从 `c fn` 导出生成 `.h`(`--have-c`)
- [ ] 包依赖和 `fetch`、`std install`(`library/std` 还在仓库里)
- [x] `--static`:驱动用 `ld/` 的链接器和 `rt/src/min.cf` 的 C 库,链出不依赖 libc 的可执行文件
- [ ] `--static` 成为默认(编译器自己用 `printf`、`fopen`、`fork` 等,得先有这些的 Coffee 版)
- [ ] `--target` 交叉编译、`--jit`
- [ ] 算术溢出和除零的陷阱(现在不检查)
- [ ] 通过 `&T`(不可变借用)给字段赋值现在不报错(编译器自己的源码这样写);要报错得先把源码里的 `&` 改成 `&mut`
- [ ] 字段和方法同名(`ret` 和 `fn ret`)
