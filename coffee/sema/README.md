# coffee/sema

Semantic analysis for Coffee, written in Coffee. It takes the parse tree from `coffee/parser`
and reports the name and declaration errors the Rust compiler reports (E101, E103, E106,
E200, E201, E600), plus unused-variable warnings.

    let a = parse(src)
    let g = new_globals()
    let m = declare_module(&g, &a, "main")
    let c = check(&a, &g, m)
    c.diags.errors()

## What it checks

- undefined names, duplicate declarations (per function, and top level), unknown types
- arity of calls to known functions; unknown and missing fields in struct literals
- `v.name` on a variable of a known class: the class or an ancestor must have it
- `break`/`continue` outside a loop, `return` outside a function, missing returns
- imports: unknown modules and names, `use * in m` copying
- a nested fn or anonymous fn reading a local of the function around it
- `#listener` names, a user `class Error`

Type errors are out of scope; that is the next stage.

## Layout

`src/sym_table.cf` (symbols, hashed names), `src/sema_diag.cf` (diagnostics),
`src/sema.cf` (the checker), `src/c_names.cf` (generated by `tools/gen_c_names.py` from
`library/cfc/{libc,libm}.cfc`), `src/sema_probe.cf` (test helpers).

## Testing

    coffee test --test-mode -I ../parser/src -I ../lexer/src -I src

`tools/corpus.py` runs the analyzer over every `.cf` file in the repository (expects no errors).
`tools/differential.py` compares it with the Rust compiler on the programs embedded in the
Rust test suite: it expects no false positives (`MISSED=1` lists what it does not catch).
Current numbers: 895 programs, 672 both accept, 62 both reject, 0 false positives, 8 missed
(type errors and missing `.cfc` libraries).
