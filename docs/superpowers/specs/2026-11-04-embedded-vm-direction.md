# 方向：体积最小的嵌入式自举语言 + 沙箱（2026-11-04）

> 2026-11-06:D1(解释器优先)和 D6 已被 [沙盒的设计](../../explanation/sandbox-design.md) 取代:没有解释器,沙盒由 JIT 的 `gs` 段访存实现。

状态：**提案，未实现**。本文只固定方向和顺序，避免自举阶段写出以后要推倒的代码。

## 定位

一句话：**小到可以嵌入宿主、能用自己编译自己、默认拒绝一切宿主能力的静态类型语言。**

它占的位置类似 wasm：核心语义很小、规则能写清楚、可被验证。不和通用语言比特性数量。

## 事实基线（2026-11-04 实测，debug 构建）

下面是写这份设计时**实际跑过**的结果，不是文档里的说法。

| 现象 | 结果 |
|---|---|
| 非 void 函数缺 `return` | 通过编译，返回随机值 |
| `match` 分支值作函数返回值 | 分支值被丢弃，返回 0 |
| 枚举 payload 的 `match` | 结果错误；多字段 `Rect(w, h)` 段错误（JIT 与 `--bin`） |
| `take(a)` 后读 `a.n`（按值传 class） | 通过编译（use-after-move 未拦截） |
| 整数除以 0 | 无检查，得到垃圾值 |
| 数组 `a[i]` 读越界 | 有检查，运行时报 `Array index out of bounds` |
| `let x = 42` | 不支持，且报错指向函数头 |
| `str + str` | 类型错误 |
| `a[i] = v`、`*r = v` | 语法错误（`Statement::Assignment` 只有变量名） |
| 泛型函数 `id(3)` / `id<int>(3)` | 报 undefined variable；`test_generic_id_infers_t` 同样失败 |
| `--jit` 符号解析 | `dlsym(RTLD_DEFAULT)`，可调用进程内任意 C 符号 |
| `cargo test --no-fail-fast` | lib 633 通过 / 9 失败；集成测试 3 个文件各 1 个失败；多个 doctest 失败 |

`tests/pattern_matching_tests.rs` 的 `match` 测试多为 `assert_compiles`，不比较运行结果，因此上面几项没被抓到。

**未验证**：切片索引是否有边界检查；`int(1)+` 加法溢出语义；上表失败测试中哪些只是环境问题（例如 `bundled libc symbol table missing`）。

## 决定

### D1 执行方式：解释器优先，JIT 以后再加

- 先定义一个很小的 IR / 字节码，再写解释器。解释器比 JIT 好做，也能更早完成自举。
- 自举后的编译器输出该 IR，由解释器运行，不依赖 LLVM。
- JIT 是以后的优化层，不改变语言语义。
- 现有 LLVM 后端保留为对照基线，不是最终运行时。

### D2 "体积"指两件事，分开度量

- **常驻体积**：随宿主分发的解释器 / JIT + 运行时。这是主要目标。
- **产物体积**：被编译程序的代码大小。
- 包管理、`coffee fetch`、`std install` 属于工具链（类比 cargo），**不计入**常驻体积。具体数字目标待定（见"未决"）。

### D3 靠语言设计减小优化器需求

- 每个抽象要有**可预测的降级方式**，成本由构造保证，不靠优化器事后找回来。
- 利用已有性质：`&`/`&mut` 互斥提供无别名信息；固定宽度整数与值类型无装箱；切片带长度。
- 泛型在单态化之外要限制实例化数量可被静态统计，避免靠函数合并救体积。

### D4 指针模型：三层，现在就定

自举的编译器代码会按这套类型来写，所以先定，再写。

| 层 | 类型 | 允许 | 保证来源 |
|---|---|---|---|
| 句柄 | `object` | 传递、比较；**禁止算术** | 类型系统 |
| 带界缓冲 | 切片 `[T]`，以及带长度的 `buf` | 索引、切分、拷贝 | 编译期证明；证明不了则运行时检查 |
| 受信任原语 | `p + n` 等原始操作 | 只出现在 `std.sys` 这类极小模块 | 人工审计，范围固定 |

- `buf` 目前没有长度，无法检查。要么给它加长度，要么废弃并用切片替代。**在自举前决定。**
- 用户代码和自举编译器的主体只用前两层。第三层的边界要列清单，不得随意扩张。
- 现有 `object + n`（GEP 字节偏移）按 D4 归入第三层。

### D5 "有保证的指针"编译后应当是裸指针

- 保证是**静态**证明时，编译结果就是裸指针访问，不留检查，性能与 C 相同。
- 证明不了的访问：要么编译期拒绝，要么保留运行时检查。检查是证明失败时的退路，不是常态。
- 因此"指针安全"的实现形式是**证明义务**，不是运行时开销。可以逐步扩展能被证明的操作（切片拆分、不相交的 `&mut`、带界偏移等）而不改变已经证明过的代码。
- 代价：能证明的范围取决于类型系统的表达力。每扩一种操作，都要在规范里写明证明规则，并配验证器检查。

### D6 `.cfc` 改为宿主能力清单（沙箱阶段）

- 沙箱内默认不能调用任何宿主函数；宿主用 `.cfc` 列出允许的符号，运行时只绑定这些。
- 沙箱模式下禁止 `dlsym(RTLD_DEFAULT)` 式的全局符号解析。
- 这一步在自举**之后**做，但 D4 的指针模型要先定。

### D7 MIR 验证器是信任基础

- 编译器自身有 bug 时，验证器是最后一道防线。至少检查：所有路径有返回值、无 use-after-move、类型一致、D4 的层级约束。
- 验证器要小到可以逐条审计。

## 顺序

1. **先修语义**（每项先写会失败的、比较运行输出的测试）：
   1. 非 void 函数的"所有路径有返回"检查，以及 `match` 的取值语义；
   2. 枚举 payload 匹配的正确性与段错误；
   3. `take(a)` 之后继续使用 `a.field` 的所有权漏洞；
   4. 语法错误定位（目前总是报在 `fn` 那一行）；
   5. 整数除零的行为（检查或明确写成错误）。
2. **补自举所需的语言能力**：见下表。
3. **定 IR 规范 + 解释器 + 验证器**（D1、D7）。
4. **用 Coffee 子集重写编译器前端**，输出 IR。
5. **沙箱**：能力清单、禁止全局符号解析（D6）。
6. **JIT**：作为解释器之上的优化层。

不要在第 1、2 步完成前开始第 4 步。

## 自举阻塞项

| 编译器需要 | 现状 |
|---|---|
| AST：带字段的枚举 + `match` | payload 匹配错误 / 段错误 |
| 函数返回 `match` 的值 | 不工作，也无缺 `return` 检查 |
| 动态数组、哈希表 | 无标准集合；泛型函数调用不工作 |
| 字符串拼接 / 构建 | `str + str` 不支持 |
| 数组元素原地修改 | `a[i] = v` 语法错误 |
| 通过引用写入 | `*r = v` 语法错误 |
| 可靠的所有权 | 存在 use-after-move 漏洞 |
| 可读的错误信息 | 语法错误定位不准 |

## 暂缓 / 不做

- 继承、`packed`、`copy`/`clean`、枚举之外的复杂模式：先冻结，不阻塞自举，也不扩展。
- 闭包捕获：目前编译器直接拒绝；自举阶段不引入。
- 包管理：留在工具链，不影响常驻体积。

## 未决

- 常驻体积的数值目标（100 KB / 1 MB / 其他）。
- "嵌入式"指嵌入宿主程序（类 Lua），还是跑在单片机上；影响内存模型与是否需要 JIT。
- `buf` 加长度还是废弃。
- 沙箱走线性内存（D4 之外的偏移表示）还是只靠类型证明；本文倾向前者更易验证，但未决定。
- 目标平台是否包含禁止可执行内存的环境（需要保留解释执行，D1 已覆盖）。
