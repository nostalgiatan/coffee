# 总体架构

这是唯一的入口。其他设计文档各讲一个局部,有出入时以这一份为准;它们的状态在末尾的"文档地图"里。

## 1. 目标和边界

| | |
|---|---|
| 要做的 | 一个静态类型、自举的编译器,带自己的后端、链接器和 JIT;JIT 是**最小占用的、可内嵌的、可沙盒的**;可以跨平台(x86-64 和 aarch64 的 Linux 现在有,Windows 和 riscv64 以后) |
| 内嵌的主要使用者 | **别的语言**(Python、Rust、Go、Lua 等),所以接口是 C ABI;Coffee 自己用它的机会小,但要留 |
| 不做的 | 解释器(JIT 是唯一的执行方式);iOS 的 JIT(系统不允许);32 位目标 |
| `coffee2` 自己 | 仍是 x86-64,能交叉编译 |

## 3. 五条原则

1. **IR 是唯一的可移植层。** 不再造"机器 IR"。x86 是两地址、aarch64 是三地址,硬统一只会让两边多一层转换。共用的是**分配器和帧**,不是指令。
2. **一个目标 = 一份数据表 + 一小组固定签名的函数。** 后端代码里出现的目标常数必须来自表。
3. **沙盒不是另一种 IR,是同一份 IR 的另一种代码生成方式**,加一个验证器。保证只有一句话(第 6 节),验证器是它的边界。
4. **每一步整理都必须让两个目标的输出逐字节不变**;有语义改动的步骤必须有测量。
5. **先量,再设计。** 这个项目里已经两次被小基准误导(见第 7 节),决定要用真实程序上的数字。

## 4. 前端和 IR

`lexer → parser → sema → types → own → ir/lower`,见 `reference/pipeline.md`。驱动把模块**压平**成一个文本再进前端。IR 是 SSA,操作表在 `op.cf`,验证器 `verify.cf`。

IR 之后的两个变换:

- **modopt**:与目标无关的优化。
- **legalize**:就地把目标不原生支持的操作改写成它支持的(`Alloc`/`Free`/`FRem` → 调用,`Switch` → 比较链,常数除法 → `SMulHi` 加移位)。读目标表里的"支持哪些操作"。

`.cir` 在 legalize **之前**落盘,所以一份 `.cir` 可以交给任何目标。

## 5. 后端

### 5.1 目标的两部分

**数据**(`target_x86.cf`、`target_a64.cf`):寄存器池和它们的保存约定、调用约定、帧头大小和上限、立即数范围、沙盒用的寄存器角色、重定位种类、运行时的系统部分。**函数**:`gen_function`、访存口、移动与常数物化、调用序列、汇编器、沙盒验证器的解码。

### 5.2 共用服务(现状)

| 服务 | 位置 | 状态 |
|---|---|---|
| 与指令集无关的分配辅助(要不要放寄存器、使用计数、地址折叠、边、提示、大小) | `regalloc.cf` | 已做,两个目标共用 |
| 栈帧布局 | `layout_frame` | 已做,参数是帧头大小、增长方向、帧上限 |
| 边拷贝的冲突判断 | `edge_hazard` | 已做;冲突怎么解决留在各目标 |
| 线性扫描骨架(通用寄存器) | `lscan_order`、`lscan_int` | 已做,两个目标共用。目标只提供寄存器表、每个值允许的寄存器位集(`allow`,x86 由调用掩码算出,aarch64 全开)和跳过标记(放进向量寄存器的浮点值);向量寄存器的分配仍在各目标 |
| 访存策略(是否受限、地址寄存器的挑选、失败计数) | `Access`(`access.cf`,`Asm.acc`) | 已做;aarch64 的汇编器共用同一个 `sbx` 开关 |
| 沙盒验证规则 | `sbxrules.cf` | 已做:两个验证器的拒绝原因都映射到 6 条共同规则(decode、unguarded、frame、protected、branch、adjacent),错误信息用同一套名字 |
| 共用反例集 | `sbxcases.cf`、`test_sbx_rules.cf` | 已做:每行是规则、目标、模式、拒绝偏移和代码;测试要求每条规则在它适用的每个目标上至少有一个反例 |
| 调用序列、聚合参数拷贝 | 各目标 | 一半重复,未抽 |

### 5.3 访存口

所有内存操作数只经 `Asm.mem`(x86;aarch64 对应 `asm_a64`),在这里决定:是不是宿主栈帧(不受限)、是不是受限访存(沙盒)。这是沙盒唯一需要改动的地方,所以沙盒的各种模式只是这个函数里的分支。

## 6. 沙盒

### 6.1 保证

**不可信的 `.cir` 不能让沙盒里的代码读写线性内存之外的东西,不能执行线性内存之外的代码,也不能做清单之外的系统调用。** 可信范围见 `sandbox-design.md` 末尾的表。

### 6.2 模型

- 线性内存是 4 GB 加保护页的保留区,指针值是区域内的偏移(存储仍是 8 字节,布局和原生相同,所以同一份 `.cir` 在沙盒和原生里的数据布局一样)。
- 地址 = 区域起点 + 32 位偏移,**由寻址机制保证**,不靠检查值:

| 模式 | 机制 | 现状 |
|---|---|---|
| `gs`(x86-64) | `67 65` 前缀,硬件做 | 有;x86 专有 |
| 基址(通用) | x86:先 `lea` 出 32 位地址再 `[r15 + s]`;aarch64:`[x28, wN, uxtw]`;riscv64:`add.uw` | x86 有;aarch64 的代码生成和验证器有,**加载器没移植** |

- **验证器**(每个 ISA 一个解码器,规则相同):只认生成器会发的指令形式;内存操作数只能是宿主帧或 `[r15 + s]`;`[r15 + s]` 紧跟写 `s` 的 32 位 `lea` 且无跳转落在其上;不许写 r15;没有系统调用、陷入、间接转移;直接转移落在指令边界。
- **宿主调用**(`jit/src/hostcall.cf`,x86-64 与 aarch64):每个登记的宿主函数带签名,跳板检查指针参数和长度、加基址、返回时减基址;没登记的仍拒绝。细节见 `jit-design.md`。

### 6.3 已定的决定和依据

| 决定 | 依据 |
|---|---|
| 指针用**偏移式**(8 字节存储,值是偏移) | 纯 32 位指针改变数据布局和 C 互操作;纯 64 位加软件检查开销大(文献里 memory64 超过 100%);真地址要靠硬件键才安全 |
| 不做"高位放片号"的分片指针 | 在 x86 上强制成本比偏移式高(36 位掩码放不进立即数),单个沙盒里换不来更低的成本 |
| 内存保护键(pkeys)只作**可选加速**,不作基础 | 本机 PKU 可用、边界约 22 ns,但拒绝路径没验证成,且 x86/ARM 专有、键只有 16 个 |
| 另一个进程做隔离:不采用 | 宿主调用变成微秒级,与"最小占用的内嵌"相反 |
| 句柄表式指针:不采用 | 每次访存多一次间接加比较;`buf`/`slice` 本来带长度 |
| **基址模式的成本是寄存器压力,不是 `lea`** | 解析器工作负载:原生 1.47、`gs` 1.53、基址 1.75;原生代码少用 r13、r14、r15 就到 1.72;去掉 60% 访存的 `lea` 没变化 |
| 已释放 r13(`lea` 进空闲寄存器 + 相邻规则) | 基址 1.75 → 1.70 |
| 已释放 r14:**镜像影子帧**(影子帧地址 = rbp 的低 32 位 + 位移,宿主栈映射成与影子栈同址) | 基址 1.70 → **1.61**(原生 1.47);SP 单元方案因侵入大被否决;完全静态叠放因调试器地址固定、多线程需每线程一份而降为将来可选 |
| `gs` 暂时保留 | 删除条件:基址模式在 `ir/bench` 和解析器工作负载上不高于 `gs` 的两倍开销 |

## 7. 要记住的教训

- 小基准(`acc`)说"减速来自 `lea`";真实工作负载说"来自寄存器压力"。两者都对,各自只适用于自己的程序。**基准要包含一个真实程序。**
- 语料对比(新旧编译器在同一棵树上输出逐字节相同)是整理步骤的门槛;`ir/tools/corpus-x86.sh`、`corpus-a64.sh`。输出约 850 MB,放磁盘,不放 `/tmp`(内存)。

## 8. JIT 和内嵌

- **映像**:代码加桩、只读数据、可写数据、槽。加载器映射成可写,填槽,再切成读执行、读、读写,**从不同时可写可执行**。外部调用经桩和槽,名字表 `Exports` 放宿主函数和先载入的模块定义的函数。
- **格式**:`.cir`(可移植对象)、`.cim`(带符号和导入的映像,CIM2)。
- **库**:`libcfjit.a`/`.so` + `cfjit.h`,纯 C ABI(整数和指针):`new/free/register/load/sym/replace/unload`。热替换的粒度是**模块**,旧模块保持映射由宿主确认安静后卸载;一次一个线程;每个模块有自己的堆。没有 `main` 的库靠 `cf_init` 给模块级变量赋值;`--pic` 把非 `c fn` 的符号隐藏;`cf_syscall` 的桩由目标层给出。
- **跨系统**:`mmap`/`mprotect` 换成 `VirtualAlloc`/`VirtualProtect`;aarch64 写完代码要做指令缓存同步;macOS 要 `MAP_JIT`;陷阱用信号或结构化异常。

## 9. 运行时

`rt/src/min.cf` 是所有系统共用的,`os_<系统>_<架构>.cf` 是系统部分(系统调用号和调用约定)。Windows 和 macOS 没有稳定的系统调用号,要换成对导入函数的调用(`c fn` 已经能声明),所以那不是"换号码"。
