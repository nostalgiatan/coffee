# JIT 的分层、热替换和预处理

状态:设计稿;其中的 `image()`(阶段 2)已实现。上下文见 [JIT 后端的设计](jit-design.md) 和 [沙盒的设计](sandbox-design.md)。

## 为什么我们的 JIT 简单

- **静态类型**:没有投机优化,不需要类型守卫、内联缓存和去优化。低阶代码和高阶代码语义完全相同,只是快慢不同。
- **所有权,没有 GC**:没有安全点、栈图、写屏障,任何指令边界都能换代码。
- **自己的后端和链接**:调用约定、寄存器破坏集、重定位、代码布局全由我们定,没有 ABI 和 PLT/GOT 的岔路。
- **`.cir` 已含整模块信息**:调用图、效应摘要、循环信息都能在产出时算好。

## 分层

- 一阶(tier 0):`.cir` 的未优化形式(`opt 0`),生成快,代码慢。往返测试已覆盖 `opt 0` 和 `opt 1` 两种。
- 二阶(tier 1):`module_opt` 之后的形式,即现在的生成路径。
- 起步看静态热度:循环里的函数、`in_loop` 内联目标直接编到二阶,省掉一阶那一遍。
- 运行时热度用采样:`SIGPROF` 采样 RIP,映射到函数,超过阈值就提升。生成的代码里没有计数器。沙盒本来就要装信号处理器,基础设施共用。

## OSR:旧帧调新代码

不换栈帧。对循环头 `H`:

1. 一个 IR 变换 `make_osr(f, H)` 生成 `f$osr`:新入口块接收一个状态缓冲区,把 `H` 处活着的值读出来,再 `Br H`;然后走正常的优化和生成。
2. 一阶代码里,循环回边处放一个热度检查,命中就 `r = call f$osr(状态)`,接着直接 `Ret r`,不执行作用域末尾的 drop,因为新代码已经接管了所有权。
3. 每次调用只触发一次,栈只多一层。

状态要的是 `H` 处的**活跃集**:块参数,加上在循环外定义、循环内使用的值(它们不经过块参数)。需要算一次活跃性,`gen` 里的区间数据是现成的。

取过地址的局部变量(`Slot`)不搬:旧帧还活着,新代码把它们的地址当参数收下。

不需要去优化,也不需要反向 OSR。

## 热替换

- 函数头 8 字节对齐,头部留一个 5 字节的 `jmp rel32` 位置。换版本是一次原子写。
- 调用点的 `rel32` 保持指向函数头。以后可以直接改调用点,要求调用点对齐到 4 字节,避免跨 cache line。
- 旧代码留到没有活跃帧使用它(用代数计数,或者一直留着,代码区够小)。

## 预处理:能提前做的不放到运行时

按时刻分:

**产出 `.cir` 之前**

- 预执行纯函数:对常量输入的纯函数(效应摘要 `f_fx` 判定),在沙盒里带燃料上限跑,把结果折成常量。不确定就放弃。
- 整模块优化好再存,`.cir` 头标志已优化。
- 静态热度写进 `.cir`:每个块的循环深度。
- 验证结果按内容哈希缓存。
- 可选的剖析节:上次运行的采样结果,下次用来排布和预编译。

**加载时**

- 一遍扫完函数表,算出调用图和用到的导入,能在生成前拒绝。
- 按 `call_order` 的层并行生成,入口函数先好先跑。
- 重定位在布局确定后一次补完。
- 预生成的镜像存成文件,按 CPU 特性分版本,启动是 `mmap`。

**运行时(后台)**

- 初始化快照:跑到第一次等待输入,存线性内存。
- 预测式提升:热函数连同它常调用的子函数一起提。

所有缓存的键都含 `.cir` 内容哈希、编译器版本、CPU 特性。
