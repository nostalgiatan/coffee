# 沙盒的设计

状态:阶段 S1 已实现(访存封闭、影子帧、堆、陷阱),S2 已按下面的简化做完(`read`/`write` 经宿主存根,按描述符授权),S3 的验证器已实现;`CAPS` 节、句柄表、配额是设计。它取代 `docs/superpowers/specs/2026-11-04-embedded-vm-direction.md` 的 D1(解释器优先)和 D6,以及 `2026-11-04-memory-system-and-bytecode.md` 的字节码部分。那两份文档为第一代 Rust 编译器和解释器写成,线性内存、带大小释放、陷阱这些想法保留,其余按本文为准。上层的 JIT 见 [JIT 后端的设计](jit-design.md)。

## 前提

- 没有解释器。JIT 是唯一的沙盒执行器。不能分配可执行内存的环境不在目标内。
- 沙盒安全和语言安全是两个独立的保证。所有权出错最多破坏沙盒自己的堆;越出沙盒只由本文的机制挡住。
- 能到达沙盒外部的东西只有三样:内存访问、控制流、导入函数。下面逐一封住。

## 一个推论:封闭靠访问,不靠检查代码

`peek8/peek64/poke8/poke64` 在 IR 里就是普通的 `Load`/`Store`,`syscall` 是对 `cf_syscall` 的 `CCall`。所以:

- 沙盒不需要在 IR 里禁止 `peek`/`poke`。它们和其他访存一样被限制在线性内存里,是安全的。
- 沙盒要拒绝的只有"调用不在清单里的外部符号"。`cf_syscall`、`malloc` 之外的 libc 名字,都在加载时因为不在能力清单里而被拒绝。
- 前端和优化器不在可信范围内。不可信的 `.cir` 也能安全执行。可信的只有生成的机器码形式和加载器。

## 内存:用 `gs` 段加 32 位地址

### 做法

加载器 `mmap` 一块 4 GB 加一页的 `PROT_NONE` 区域,基址按 4 GB 对齐,只把前 `limit` 字节改成可读写,并用 `arch_prctl(ARCH_SET_GS)`(或 `wrgsbase`)把 `gs` 段基址设为区域起点。沙盒代码的每次访存都写成

```
67 65 <REX> <opcode> <modrm> [sib] [disp]     ; mov rax, gs:[ecx + edx*8 + 16]
```

`0x67` 把有效地址的计算限在 32 位,环绕在 4 GB;`0x65` 加上 `gs` 基址。结果总在区域内,不管寄存器里是什么。

### 为什么选它

| | 基址寄存器加掩码 | `gs` 加 `0x67` |
|---|---|---|
| 每次访存的额外指令 | 一条 `and` 或 `mov r32,r32` | 零,只多两字节前缀 |
| 占用寄存器 | 1 个(可分配的 10 个里) | 0 个 |
| 越界 | 绕回(掩码)或要保护区 | 超出 `limit` 的页是 `PROT_NONE`,访问即陷阱 |
| 保护区 | 要 | 只在区域尾部 1 页,防止末尾的多字节访问越出 |

关键是地址 32 位环绕:位移为负也只会落回区域内,所以不需要区域前面的保护区,也不需要限制折叠进寻址的位移大小。

这个做法来自 "Segue"(Narayan 等,2025)一类工作。论文给出的是个位数百分比的开销改善,我们要在自己的基准上量,不照抄数字。

### 指针的值

指针是 64 位值,低 32 位是线性内存里的偏移;高位被忽略,因为每次访问都截断。沙盒代码因此可以做任意指针算术,不会越界,最多是访问到自己内存里的别处。`0` 号偏移所在的前 64 KB 保持 `PROT_NONE`,空指针访问是陷阱。

### 哪些访存要改

`Gen` 里所有内存操作最后都走 `Asm` 的 `rmem`、`rmem_idx`(`load`、`store`、`load_idx`、`store_idx` 经过它们)。聚合拷贝是逐字的 `load`/`store`,没有 `rep movs`,所以没有绕过的路径。规则:

- 基址寄存器不是 `rbp`、`rsp` 的访存,是沙盒访存,加 `0x67 0x65`,且基址和变址寄存器按 32 位编码。
- 基址是 `rbp`、`rsp` 的访存是宿主栈访问(寄存器溢出、保存的寄存器),不加前缀。沙盒代码不能取得宿主栈的地址,所以不需要保护。
- `lea` 只算地址,不访存,不变。

各个操作:

| 操作 | 沙盒模式 |
|---|---|
| `Load`、`Store`、`Field`、`Index` 折叠进寻址 | 加前缀,寻址整体 32 位 |
| `Slot`(取地址的局部) | 放进影子栈(见下),值是线性内存偏移 |
| `StrLit`、全局变量、`Undef` 的零块 | 常量偏移,`mov r32, imm32`,不再用 `lea_rip` |
| `Alloc`、`Free` | 调沙盒运行时的 `malloc`/`free`(同一份 IR,同样的访存规则) |
| `Call` | 照旧,目标在同一模块里 |
| `CCall` | 只能是能力清单里的导入,见下 |
| `FnAddr`、`CallI` | 函数表下标加范围检查,表在线性内存之外;v1 可先拒绝 |
| `FRem` 等落到 libm 的操作 | 导入(宿主的纯函数)或软件实现 |

## 栈

- 宿主栈和沙盒的线性内存是两块东西。返回地址和保存的寄存器在宿主栈上,沙盒代码取不到它们的地址,所以不能改返回地址。这是控制流封闭的基础,不能为了省事把栈放进线性内存。
- 沙盒在自己的 `mmap` 栈上运行,栈底有保护页。栈溢出是 SIGSEGV,变成陷阱,宿主栈不受影响。
- 取过地址的局部变量(`Slot`)放在线性内存里的影子栈。影子栈指针先放在线性内存的固定偏移处,有 `Slot` 的函数在进入和退出时各读写一次。如果测出这一步太贵,再占一个寄存器。

## 线性内存布局

```
0        64 KB          空指针保护(PROT_NONE)
64 KB    .rodata        字符串等
         .data / .bss   全局变量
         影子栈         向下增长,大小固定
         堆             向上增长,到 limit
limit    之后            PROT_NONE,到 4 GB
```

`.rodata` 可以设成只读页(加载时把这些页 `mprotect`),沙盒代码不能改常量。`limit` 由宿主给定,同时就是内存配额。

## 导入和能力清单

- `.cir` 加一个 `CAPS` 节:允许的导入名和签名。
- 加载器扫描 `NAME` 里被 `CCall` 用到的外部名字,不在清单里或签名不符就拒绝加载。
- 导入由宿主提供。调用一次导入是一个跳板:切到宿主栈、校验参数、调宿主函数、切回。宿主得到的指针参数是 `(偏移, 长度)`,先检查范围,再按 `gs` 基址访问。
- `object` 句柄在沙盒里是宿主句柄表的下标,没有算术。

沙盒运行时 `sbx.cf` 取代 `min.cf`:`malloc`/`free`/`calloc`/`memcpy`/`strlen`/`strcmp` 全部写在线性内存上(带大小类的空闲链表加堆顶指针,见 11-04 的 M5)。`exit`、`write`、`read` 等是导入。堆耗尽是陷阱。

## 陷阱

越界、栈溢出、除零、`Unreachable`、堆耗尽都是陷阱:终止沙盒实例并给宿主一个错误码,不是未定义行为。

- 加载器用原始 `rt_sigaction` 装 SIGSEGV、SIGFPE、SIGILL 的处理器(`SA_SIGINFO|SA_ONSTACK`),用 `sigaltstack` 跑,自带 `rt_sigreturn` 的跳板。
- 处理器检查出错的地址或 RIP 是否在沙盒的区域、代码或栈里。是,就把被中断的 RIP 改到陷阱出口,出口恢复进入时保存的宿主 `rsp` 并返回。不是,说明是宿主自己的错误,照常终止。
- 可选:CPU 配额用 `setitimer` 的 SIGALRM,同一个处理器。在导入函数内部时只置标志,返回沙盒前检查。

## 可信范围,和怎样把它缩小

沙盒封闭的依据是 `Gen` 生成的访存都带前缀。所以 `Gen` 和 `Asm` 有 bug 就破坏隔离。第一版接受这一点,因为它们本来就必须正确。

第二道防线是一个机器码验证器,在加载时扫描生成的字节(NaCl、RockSalt 的做法):

- 每条访存要么是 `0x67 0x65` 加 32 位寻址,要么基址是 `rbp`/`rsp`。
- 没有 `syscall`、`int`、`wrgsbase`、段寄存器装入、`rsp` 的算术(除了固定的函数序言和尾声)。
- 直接转移的目标是指令边界;间接转移只通过函数表。

`Asm` 只生成有限的几种编码,验证器只需认这几种,预计几百行。有了它,可信范围从 `Gen`(约 80 KB)缩到验证器和加载器,不可信的 `.cir` 就可以放心加载。

## 做不到的和先不做的

- **旁路攻击**(Spectre 等):不防。
- **没有 MMU 或 32 位的宿主**:`gs` 方案不适用。回退是基址寄存器加掩码,区域按 2 的幂,每次访存一条 `and`。`Gen` 的沙盒参数留三个取值:无、`gs`、掩码。先只做 `gs`。
- **同一进程里实例很多**:每个实例占 4 GB 虚拟地址,用户态空间约 128 TB,上限约几万。更多时用掩码模式的小区域。
- **32 位指针**(内存里省一半空间):以后的优化,要把 `rsize` 的指针宽度参数化,影响整个 lower 和 gen。

## S1 的实现记录

按上面的设计做了,和设计的差别与新发现如下。

- **影子帧**:聚合值(元组、`buf`、切片)和 `Slot` 都放进影子帧,以 r14 为基址。这样所有经过非 `rbp`/`rsp` 基址的访存都是沙盒访存,不需要区分"宿主指针"。聚合参数和 `sret` 也走影子帧,因为它们是以指针传递的。r14 不参与寄存器分配。大于 32 KB 的影子帧在生成时被拒绝,避免跨过栈底保护区。
- **`lea` 不加前缀**:`0x67` 会把整数运算用的 `lea` 截成 32 位,所以 `lea` 和以 `rbp`/`rsp` 为基址的访存不加。
- **绝对地址**:rodata 和全局变量的引用在沙盒里是 `mov r32, imm32`,配 R_X86_64_32 重定位,目标是线性内存偏移。
- **函数值**:沙盒里的 `CallI` 生成时被拒绝;取函数地址(`FnAddr` 指向代码)在映像阶段被拒绝(`err` 3)。
- **`cf_syscall` 作为映像里的代码**:`exit`(60、231)回到宿主;`mmap`(9)从线性内存里的堆取页;其余一律返回 `-ENOSYS`。堆指针在线性内存开头 16 字节的头里。所以数组、字符串等需要分配的程序已经能跑,输出(`write`)还不行,要等 S2 的导入。
- **宿主侧**:`cfjit --sandbox`。保留 4 GB 加 128 KB 的 `PROT_NONE` 区域,`arch_prctl` 设 `gs`;沙盒在自己的栈上跑,栈底有保护页;控制块在沙盒看不到的内存里;SIGSEGV、SIGBUS、SIGFPE、SIGILL 在备用栈上的处理器里转成陷阱:出错的 RIP 若在沙盒代码里,就改到陷阱出口,否则 `exit_group(134)`。存根用 `Asm` 生成。
- **不可达函数剔除**:`prune_unreached` 从 `main` 出发,按调用图(含 `Alloc`/`Free` 隐含的 `malloc`/`free`、`FRem` 的 `fmod`)只生成可达的函数。运行时随每个模块带来,不剔除的话每个沙盒镜像都要带上整个 `min.cf`。
- **测试**:`jit/tests/test_sandbox.cf` 覆盖正常运行、堆、`exit`、空指针、远地址、除零、无限递归和高位地址别名。`compare.sh` 加了 `SANDBOX=1`:lexer、parser、sema、types、own 的 31 个测试文件和 compat 的 36 个得到与原生相同的退出码;compat 里另外 27 个需要 `fork`/`exec`(它们调用编译器),在沙盒里本来就做不到。

遇到的编译器问题:`return clone a.c`(克隆局部类的一个字段)得到的缓冲区之后会被零填充,像是与 `a` 一起被释放了。绕过方法是把字节复制到新的 `Txt` 里再返回。这是一个待查的编译器缺陷,没有最小复现,尚未修复。

## S2 的实现记录

设计里的"导入"在这里缩成两个系统调用,因为沙盒里的程序只有一条出口:`cf_syscall`(`min.cf` 的 `write` 等都经它)。没有 libc,没有 `object` 句柄,所以不需要导入表和句柄表,也就没有 `CAPS` 节;授权由宿主在启动时给定。

- **跳板**:映像里的 `cf_syscall` 对号码 1(write)和 0(read)各有一个 16 字节的 `jmp [rip+2]` 加 8 字节槽,槽由加载器填成宿主存根的地址。汇编器会缩短跳转,所以加载器在生成后的字节里找这个字节序列定位槽,不用生成时的偏移。
- **宿主存根** `stub_io`:全系统唯一含 `syscall` 指令的地方(S3 的验证器据此规定其余代码不许含它)。它检查三件事,任何一件不满足都不进内核:描述符 ≤ 63 且在控制块的表里(`ctrl + 512 + 64*n + fd`)置了位,否则 `-EBADF`;长度不超过 `limit`,偏移取低 32 位,偏移加长度不超过 `limit`,否则 `-EFAULT`;之后把偏移加上区域基址,发出 `read` 或 `write`。存根在沙盒的栈上跑,不切栈:它不调用宿主函数,不需要宿主栈。
- **授权**:`cfjit prog.cir --sandbox --allow=stdin,stdout,stderr`,是其中的一个子集,`--allow=` 是全不允许,缺省三个全开。其余号码仍然返回 `-ENOSYS`。
- **测试**:`test_sandbox.cf` 里 7 个新用例——输出到达、只开 stderr 时 stdout 写失败、缓冲区长度 2^32、偏移靠近 4 GB 末尾、描述符 77 都失败。`compare.sh` 的沙盒模式现在也比较输出:前端 5 个目录的 31 个文件输出和退出码都与原生相同。
- **没做的**:`CAPS` 节(程序现在不声明需要什么,宿主给什么它就能用什么);`open`、`getpid`、时间等其他调用;配额。

## S3 的实现记录

`ir/src/sbxcheck.cf`,约 300 行,`cfjit --sandbox` 在生成之后、运行之前对模块的机器码(不含映像里的 `cf_syscall` 和存根)整段检查,不通过就不运行(退出码 2,信息里带偏移、原因号和该处的字节)。有了它,`.cir` 是否可信不再取决于 `Gen` 的正确性。

- **解码**:一个只认 `Gen` 和 `Asm` 会发的那些编码的长度解码器,从头线性地走到尾。未知的操作码一律拒绝。前缀只在它们真会出现的指令上接受(`66` 只配 16 位存储和三条 SSE 移动,`F2`/`F3` 只配标量浮点),否则立即数的长度会和处理器的看法不同,这是这类检查最常见的漏洞。`67` 和 `65` 必须一起出现。
- **访存**:要么带 `67 65`(`gs` 加 32 位寻址),要么是 `[rbp + disp]`:|disp| 小于 32768,且不是 `[rbp]` 和 `[rbp+8]`(保存的 rbp 和返回地址)。`rsp` 作基址、`rip` 相对、其他段前缀都拒绝。`lea` 不访存,不限制。
- **rsp 和 rbp**:只能按函数帧的方式变:`push`,`pop rbp`,`mov rbp, rsp`,`mov rsp, rbp`,`lea rsp, [rbp - n]`,`leave`,`add/sub rsp, imm`(imm ≤ 32768)。`pop rsp`、`mov rsp, rax` 之类都拒绝。沙盒栈的保护区因此加到 64 KB,大于任何一个帧,帧不会跨过它。
- **转移**:直接跳转和调用的目标必须是某条指令的起点(第二遍,用第一遍记下的边界),或者是 `cf_syscall` 的入口。没有间接跳转和间接调用,`syscall`、`int`、`wrgsbase` 不在白名单里。
- **没有证明的**:`push` 的平衡、`ret` 前栈是否对齐不检查;这些出错最多让沙盒自己崩溃,因为返回地址所在的两个字无法写入,栈指针的移动受限。对执行流的另一个入口是信号处理器改的 RIP,它由宿主存根控制。
- **测试**:`ir/tests/test_sbxcheck.cf` 用手写的字节序列测 29 种情形(接受 6 种、拒绝其余),`compare.sh` 的沙盒模式对 67 个文件的全部生成代码过验证。
